# Deployment records

`script/Deploy.s.sol` writes one record per network at `deployments/<chainId>.json`, with exactly these keys: `chainId`, `commit`, `engineForkCommit`, `sessionEngine`, `sessionValidator`, `urp`, `universalGateway`, `universalExecutorModule`, `walletImplementation`, `factoryProxy`, `factoryLogic`. The four wiring keys are named after the wallet implementation's view functions so that **S-05** (`test/integration/DeploymentRecord.t.sol`) can compare the record against the deployed bytecode mechanically — a record written from intent rather than from what was actually deployed turns that test red. **There are two commit keys and they are not interchangeable:** `commit` is this repo's HEAD when the script ran, `engineForkCommit` is the vendored SmartSession pin (`7dc20e4`); they share a value only until this repo's first commit, so a test comparing the wrong one would pass silently forever. **Local records are never committed** — `deployments/*.json` is gitignored, because a local `anvil` record would otherwise overwrite a real network's and because the addresses in it mean nothing outside the machine that produced them; publish a record deliberately, by a separate reviewed change, never as a side effect of running the script. The `factoryProxy` address is the permanent, user-facing one: it goes into the SDK and every integration, and it does not change across factory-logic upgrades.

**Partial deployments.** When only `AGW` and `AGWFactory` change, `script/DeployWalletAndFactory.s.sol` deploys a new wallet implementation, factory logic and factory proxy over the existing engine, URP and validator (env `SESSION_ENGINE`, `URP`, `SESSION_VALIDATOR`, plus `CHAIN_ID`, `UNIVERSAL_GATEWAY_PC`, `FACTORY_ADMIN`). It checks the reused contracts before broadcasting, writes the same keys as `Deploy.s.sol`, and adds `reused`, which lists the keys carried over from the previous deployment (their source is that deployment's commit, not `commit`). v5 on Donut was deployed this way.
